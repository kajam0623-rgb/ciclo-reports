4. 구조화 데이터 (JSON-LD · LocalBusiness)

구조화 데이터가 하나도 없습니다. AI가 답변에 가져다 쓰는 1순위 재료입니다.

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "LocalBusiness",
  "name": "www.xn--vf4bnjl0p3a.com",
  "url": "https://www.xn--vf4bnjl0p3a.com",
  "telephone": "[대표번호]",
  "address": {
    "@type": "PostalAddress",
    "addressCountry": "KR",
    "addressRegion": "[시도]",
    "addressLocality": "[시군구]",
    "streetAddress": "[도로명 주소]"
  },
  "openingHoursSpecification": [
    {
      "@type": "OpeningHoursSpecification",
      "dayOfWeek": [
        "Monday",
        "Tuesday",
        "Wednesday",
        "Thursday",
        "Friday"
      ],
      "opens": "[09:30]",
      "closes": "[18:30]"
    }
  ],
  "sameAs": [
    "[네이버 플레이스 URL]",
    "[인스타그램 URL]"
  ]
}
</script>

</head> 바로 위에 붙이세요. 대괄호 부분만 채우면 됩니다.

5. FAQ (질문형 소제목 + FAQPage)

AI는 질문-답변 한 쌍을 그대로 인용합니다. 이 형태가 없으면 인용 단위가 없습니다.

<h2>[자주 받는 질문 1]</h2>
<p>[답변 2~3문장]</p>

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "[자주 받는 질문 1]",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "[답변 2~3문장]"
      }
    },
    {
      "@type": "Question",
      "name": "[자주 받는 질문 2]",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "[답변 2~3문장]"
      }
    },
    {
      "@type": "Question",
      "name": "[자주 받는 질문 3]",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "[답변 2~3문장]"
      }
    }
  ]
}
</script>

화면에 보이는 질문·답변과 JSON-LD 내용이 같아야 합니다.

홈페이지 최상단에 robots.txt 로 저장 → https://www.xn--vf4bnjl0p3a.com/robots.txt 에서 열려야 합니다.

8. 작성·수정일 표기

AI와 검색엔진은 최신 정보를 우선합니다. 날짜가 없으면 오래된 문서로 취급됩니다.

<p>최종 수정일: <time datetime="2026-09-14">2026. 09. 14</time></p>

<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebPage",
  "url": "https://www.xn--vf4bnjl0p3a.com/",
  "dateModified": "2026-09-14"
}
</script>

용어 풀이 본문에서 점선 밑줄 친 말에 마우스를 올려도 보입니다

구조화 데이터사업장 정보를 기계가 알아보게 정리한 데이터. AI가 답변에 가져다 쓰는 1순위 재료.
내부 링크우리 홈페이지 안에서 페이지끼리 연결한 링크.
렌더 차단 CSS화면이 그려지기 전에 먼저 다 받아야 하는 디자인 파일. 개수가 많으면 첫 화면이 늦게 뜬다.
브레드크럼"홈 > 서비스안내 > 상세페이지" 처럼 현재 위치를 보여주는 경로 표시.
색인읽어간 페이지를 검색엔진이 자기 데이터베이스에 저장하는 것. 색인이 안 되면 검색해도 안 나온다.
앵커한 페이지 안에서 아래로 스크롤만 이동시키는 링크(#표시). 별도 페이지가 아니라서 검색결과에 따로 안 잡힌다.
원페이지모든 내용이 한 장에 다 들어 있고 메뉴는 스크롤만 시키는 구조. 보기엔 깔끔하지만 검색에는 페이지 1개로만 잡혀 불리하다.
전송 압축홈페이지 파일을 압축해서 보내는 기능. 켜두면 로딩이 눈에 띄게 빨라진다.
지연 로딩화면에 보이는 사진부터 먼저 불러오고 아래쪽 사진은 나중에 불러오는 기법. 첫 화면이 빨리 뜬다.
쿼리스트링주소에 ? 뒤로 붙는 부분(예: ?id=37). 검색엔진이 같은 페이지로 오해하기 쉽다.
크롤링검색엔진 로봇이 홈페이지를 돌아다니며 내용을 읽어가는 것.
헤딩제목 태그(h1·h2·h3…). 문서의 목차 구조를 만든다.
alt이미지 설명 문구. 눈에는 안 보이지만 검색엔진은 이것으로 사진 내용을 파악한다.
Article구조화 데이터 종류 중 하나. 칼럼·게시글 정보를 담는 형식.
canonical같은 내용이 여러 주소로 열릴 때 "이게 대표 주소다"라고 지정하는 표시. 없으면 검색엔진이 점수를 나눠 매긴다.
description검색결과에서 제목 아래 나오는 2줄짜리 설명문.
E-E-A-T구글이 콘텐츠를 평가하는 4가지 기준 — 경험·전문성·권위·신뢰성. 누가 썼고 믿을 만한가를 본다.
Entity검색엔진과 AI가 인식하는 "우리 브랜드라는 하나의 대상". 이게 흐리면 이름이 비슷한 다른 곳과 섞인다.
FAQPage자주 묻는 질문을 구조화 데이터로 표시한 것. AI가 그대로 답변으로 가져가기 가장 쉬운 형태.
h1페이지의 대제목. 한 페이지에 하나만 있어야 "이 페이지 주제는 이것"이라고 검색엔진이 이해한다.
h2페이지 안의 소제목. 글을 단락으로 나눠주는 역할.
HTTPS자물쇠 표시가 붙는 보안 연결. 없으면 브라우저가 "안전하지 않음" 경고를 띄운다.
JSON-LD사람 눈에는 안 보이지만 검색엔진·AI가 읽는 정보 카드. 상호·주소·전화·영업시간을 기계가 알아보는 형식으로 적어둔 것.
LocalBusiness구조화 데이터 종류 중 하나. "여기는 오프라인 매장·사업장이다"라고 알려주는 형식.
meta description검색결과에서 제목 아래 나오는 2줄짜리 설명문. 없으면 구글이 본문에서 아무 데나 잘라 쓴다.
NAP이름(Name)·주소(Address)·전화(Phone). 이 셋이 모든 곳에서 똑같아야 지역 검색에 유리하다.
noindex"이 페이지는 검색결과에 넣지 마세요"라는 표시. 실수로 켜두면 검색에서 통째로 사라진다.
og:site_nameSNS나 카톡에 링크를 붙였을 때 표시되는 사이트 이름.
Organization구조화 데이터 종류 중 하나. 기관·회사 정보를 담는 형식.
robots.txt홈페이지 최상단에 두는 안내문 파일. 검색 로봇에게 어디를 봐도 되는지 알려준다.
sameAs구조화 데이터 항목. 네이버 플레이스·인스타그램 등 우리 쪽 다른 공식 계정 주소를 적어두는 칸. AI가 이름이 비슷한 다른 곳과 헷갈리지 않게 해준다.
SEO검색엔진 최적화. 네이버·구글 검색 결과에 잘 노출되게 홈페이지를 정리하는 일.
sitemap.xml홈페이지에 어떤 페이지들이 있는지 목록으로 정리한 파일. 검색엔진이 빠짐없이 찾아가게 해준다.
title 태그브라우저 탭과 검색결과 맨 윗줄에 굵게 나오는 제목.
viewport모바일 화면 크기에 맞춰 보이게 하는 설정. 없으면 휴대폰에서 글씨가 깨알같이 작게 나온다.
